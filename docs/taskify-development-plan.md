# Taskify 개발 계획 및 우선순위 TODO

`docs/pre-development-checklist.md`에 남겨진 답변을 기준으로, 실제 개발 착수를 위한 작업 계획과 우선순위 TODO를 정리합니다.

## 1. 확정된 기준

### 1-1. 프로젝트 / 기술 기준

- API `teamId`는 `22-3`을 사용
- 구현 기준 디자인은 Figma 우선
  - [https://www.figma.com/design/FqfFEBAvqN3Cl05hMTQwlP/Taskify](https://www.figma.com/design/FqfFEBAvqN3Cl05hMTQwlP/Taskify)
- 폴더 구조는 `docs/folder-structure.md`의 현재 제안안을 그대로 사용
- TypeScript 프로젝트로 진행하며 `js` 관련 규칙은 무시
- 커밋 규칙은 `docs/convention.md` 기준 우선 적용

### 1-2. 인증 / 라우팅 기준

- Access Token은 `localStorage`에 저장
- API `401` 응답 시 `/login`으로 리다이렉트
- 로그인 상태에서 `/` 접근 시 `/mydashboard`로 이동
- 대시보드가 없더라도 `/mydashboard`로 이동

### 1-3. 권한 / 인터랙션 기준

- owner 전용 기능
  - 대시보드 수정
  - 멤버 삭제
  - 초대
- 일반 멤버도 카드/컬럼 관련 생성, 수정, 삭제 가능
- 같은 컬럼 내부 카드 순서 변경 가능
- 카드 순서는 API 필드가 아니라 클라이언트 `index` 기반으로 관리
- 외부 DnD 라이브러리는 사용하지 않음

### 1-4. UI / 상태 관리 기준

- 알림 UI는 브라우저 기본 `alert/confirm` 대신 커스텀 모달/토스트로 통일
- 상태 관리는 `fetch + Context API + React 기본 기능`만 사용
- 초대 목록 검색은 클라이언트 필터링으로 처리
- 모바일 상세 페이지 규칙
  - 사이드바는 폭을 줄이고 컬러만 표시
  - 대시보드는 컬럼을 가로 스크롤하지 않고 세로 배치
  - 헤더 액션 버튼은 축소된 상태로 유지

## 2. 개발 전략

프로젝트는 현재 문서 중심의 초기 상태이므로, 아래 순서로 진행하는 것이 가장 안전합니다.

1. **기반 세팅 먼저**

- React + TypeScript 앱 부트스트랩
- Tailwind / ESLint / Prettier / Husky / Router / alias 정리

2. **공통 기반 먼저**

- API fetch 레이어
- 인증 컨텍스트
- 라우트 가드
- 공통 레이아웃 / 공통 UI 컴포넌트

3. **사용자 진입 흐름 먼저**

- 랜딩
- 로그인
- 회원가입
- 인증 후 이동 흐름

4. **도메인 핵심 화면 순차 구현**

- 내 대시보드
- 대시보드 상세
- 카드 / 컬럼 / 댓글
- 대시보드 수정 / 마이페이지

5. **마지막에 QA / 반응형 / 예외 처리 정리**

## 4. 가장 먼저 시작할 작업

## 6. 리스크 및 대응

### 리스크 1. 카드 순서 저장은 API 미지원

- 현재 명세상 카드 정렬 순서용 필드가 없음
- 대응:
  - 1차 구현은 클라이언트 index 기반 정렬로 처리
  - 필요 시 새로고침 후 순서 유지 정책을 별도로 확장

### 리스크 2. 상태 관리 도구 제한

- React Query 같은 서버 상태 라이브러리를 사용하지 않음
- 대응:
  - fetch 훅 / context / 로컬 상태 역할 분리
  - 페이지 단위 fetch 책임을 명확히 나눔

### 리스크 3. 커스텀 모달 / 토스트 일원화 필요

- 기본 alert를 쓰지 않으므로 공통 UX 컴포넌트 품질이 중요
- 대응:
  - 초기에 Modal / Toast 시스템부터 먼저 구축

## 7. 현재 기준 미확정 또는 구현 시 가정할 항목

### 미확정

- 일반 API 에러의 한국어 문구를 문서 기준으로 모두 고정할지 여부

### 구현 가정

- 명시된 에러 문구는 요구사항대로 고정
- 그 외 일반 에러 문구는 공통 에러 매핑 규칙을 정의해 처리
- 카드 동일 컬럼 내 순서 변경은 우선 세션 기준 UI 상태로 관리

## 8. 결론

가장 먼저 할 일은 **기반 세팅 + 공통 인프라 + 공통 UI 구축**입니다.
이 부분이 끝나면 이후 페이지 개발은 병렬적으로 확장 가능합니다.

즉, 시작 순서는 아래처럼 가져갑니다.

1. 프로젝트 초기화
2. Tailwind / lint / alias / router 설정
3. 폴더 구조 생성
4. fetch / auth / route guard
5. 공통 UI 구축
6. 인증
7. 대시보드 기능 구현
